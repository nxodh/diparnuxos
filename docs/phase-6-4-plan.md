## xfwm4 조사(항목 4)

- 최소 세션(xfwm4 와 터미널)에서는 Opereta 테마, 기본 테마, xfwm4 합성 켬/끔 어느 쪽도 재현되지 않았다.
- 전체 세션에서 재현되었고, 구성 요소를 하나씩 켜서 **picom 이 있을 때만** 생기는 것을 확인했다(패널과 독은 무관).
- xfwm4 4.20 의 `compositor.c` 에서 `find_cwindow_in_screen()` 이 합성이 꺼진 동안 NULL 인 `cwindow_hash` 를 조회한다. 외부 합성 관리자가 창을 리다이렉트할 때 이 경로가 불린다. 조회 결과는 NULL 이고 동작은 이어지므로 무해하다. xfwm4 의 상위 문제이며 우리 테마와는 무관하다.
- 로그만 늘 뿐이고(`~/.xsession-errors` 는 로그인마다 새로 만들어진다) 동작에 영향이 없어 고치지 않는다. 합성을 xfwm4 로 바꾸면 사라지지만 picom 의 둥근 모서리와 그림자를 잃으므로 택하지 않았다.

## 실기에서만 확인할 수 있는 것(이전과 같음)

picom 과 NVIDIA 오픈 드라이버, 창 가장자리, Wi-Fi·블루투스 페어링·오디오 출력, Windows(BitLocker) 공존 부팅, CUDA 런타임과 GPU 추론, HiDPI 와 다중 모니터. 독의 모양은 컨테이너 스크린샷으로만 확인했다.

## 반영하지 않은 것

AF_VSOCK generator 오류(가상 머신 한정), live-config 의 기본 그룹 중 없는 그룹(powerdev, scanner, debian-tor) 경고, MTRR/ACPI/TSC 경고(에뮬레이션), 블루투스 서비스의 D-Bus 재활성화(정상).
