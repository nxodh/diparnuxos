# 0.5.1 설계: 첫 번째 이름 변경과 새 로고

- 확인 날짜: 2026-10-13
- 상태: 구현했고 컨테이너 시험을 통과했다. CI 결과는 [verification-phase-5-1.md](verification-phase-5-1.md)에 적는다.

이 문서는 **이전 이름을 적지 않는다**(요구 R4). 이전 이름은 "이전 이름"으로 표기한다.

> 0.6.0 에서 OS 이름이 한 번 더 바뀌었다([phase-6-design.md](phase-6-design.md)). 이 문서는 0.5.1 시점의 설계 기록이며 아래 이름 규칙의 "이후" 칸은 0.5.1 때의 값이 아니라 지금의 이름으로 적혀 있다.

## 1. 요구

| 번호 | 내용 |
|---|---|
| R1 | OS 이름을 이전 이름에서 새 이름으로 바꾸고 시스템 전체에 적용한다 |
| R2 | 새 로고에 맞춰 디자인을 수정한다 |
| R3 | GitHub 저장소 이름을 새 이름에 맞춰 바꾼다(`<이름>os` 형식) |
| R4 | 0.5.1 부터 이전 이름의 흔적이 없다. 호환 별칭, 이전 경로, 이전 이름을 받는 `Replaces`/`Conflicts` 를 두지 않는다 |
| R5 | git 이력은 다시 쓰지 않는다. 과거 커밋 메시지, 이전 PR, Actions 기록에는 이전 이름이 남는다 |

## 2. 새 로고

- 원본: `assets/brand/source/opereta-logo.png`(1265×1244 RGBA, 배경 투명).
- 밝은 회색(`#F0F0F0`) 원 위에 검정(`#000000`) 굵은 글자 D. D 안쪽의 삼각형 구멍으로 원 색이 비친다. 흑백 두 가지뿐이라 기존 팔레트를 그대로 쓴다([design.md](design.md)).
- 원본은 정사각형이 아니고 가장자리에 반투명 얼룩이 있다. 생성 스크립트가 불투명 화소에서 원의 중심과 반지름을 구해 깨끗한 원 마스크로 다시 잘라 1024×1024 기준 이미지를 만든다.

## 3. 이름 규칙

| 이전 | 이후 | 쓰임 |
|---|---|---|
| 첫 글자만 대문자 형태 | `Opereta` | 표시 이름, 문서, 번역 |
| 소문자 형태 | `opereta` | 명령, 패키지, 경로, 그룹, 유닛, 모듈 |
| 대문자 형태 | `OPERETA` | 환경 변수, 상수 |
| 소문자 형태 + `os` | `operetaos` | 저장소, Go 모듈 경로, 애플리케이션 ID |

세 이름이 모두 8자라 표 정렬과 고정 폭 가정이 깨지지 않는다.

적용 범위: 패키지 9종, 실행 파일, systemd 유닛, `/var/lib`·`/run`·`/usr/lib`·`/usr/share`·`/etc` 아래 경로, 계정 그룹과 예약어, 환경 변수, 설정 파일(`opereta.conf`), Go 모듈 경로, Python 패키지(`opereta_cc`), gettext 도메인, 애플리케이션 ID, ISO 볼륨 이름, `os-release`, 테마 이름, CI 아티팩트 이름, 한국어 번역, 문서 전체, 파일·폴더 이름.

## 4. 한 일

| 묶음 | 내용 | 확인 |
|---|---|---|
| 치환 | 추적 파일의 내용과 파일·폴더 이름을 한 번의 치환으로 바꿨다. 치환 스크립트는 이전 이름을 담으므로 저장소 밖에서 한 번만 실행했고 커밋하지 않았다 | 추적 파일 어디에도 이전 이름이 없다 |
| 자산 | 이전 로고의 원본과 파생 이미지를 지우고 새 로고에서 아이콘(원형 16~512), 마크(흰색, 검정), 배경 마크, 설치기 이미지, GRUB 참고 이미지, xfwm4 테마 이미지를 다시 만들었다 | 화면 캡처 |
| 디자인 | 시작 메뉴 단추(원 안의 D), 로그인 아바타(원형), 배경 마크(`#3A3A3A` 의 D), 설치기 이미지가 새 로고를 쓴다. 팔레트와 모서리 규칙(6px)은 그대로다 | 화면 캡처 |
| 검사 | `scripts/check-legacy-name.sh`(추적 파일의 경로와 내용, `make check-legacy-name`, CI 린트), 이미지 검사(파일 목록, 패키지 데이터베이스, 설정 파일), QEMU 라이브 세션(파일 이름, 유닛, 그룹, `os-release`) | 아래 참고 |
| 정리 | 실수로 추적된 Python 바이트코드(`__pycache__`)를 추적에서 빼고 `.gitignore` 에 넣었다. 이 파일들에 이전 이름이 들어 있었다 | |

## 5. GitHub

| 항목 | 방침 |
|---|---|
| 저장소 이름 | `<이름>os` 로 변경한다. 0.5.1 이 CI 를 통과한 뒤 `main` 병합 직전에, 실행 전에 알린다 |
| 원격 주소 | 변경 직후 `git remote set-url origin` 으로 갱신한다 |
| 이전 주소 | GitHub 가 새 주소로 리다이렉트한다. 이전 이름의 외부 흔적이며 제거할 수 없다 |
| 영향 | Actions 캐시(CUDA 컴파일 약 1시간)와 아티팩트 이름이 바뀐다. 열린 PR 과 브랜치는 유지된다 |
| 이력 | 다시 쓰지 않는다(R5) |
| 로컬 폴더 | 이전 이름의 로컬 폴더는 Claude 프로젝트 메모리 경로에 쓰이므로 사용자가 직접 옮긴다 |

## 6. 수용 기준

1. 이전 이름이 추적 파일(경로와 내용), 빌드한 이미지, 라이브 세션, 설치된 시스템에 없다.
2. 기존 시험이 모두 통과한다.
3. `os-release` 의 `NAME`, `ID` 가 새 이름이다. ISO 볼륨 이름이 새 이름이다.
4. 로그인 화면, 데스크톱, Control Center, 설치기의 캡처에 새 로고가 표시된다(자동 판정은 "비어 있지 않음"까지, 모양은 사람이 확인한다).
