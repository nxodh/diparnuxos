단위 시험이 확인하는 보안 성질:

- 웹 관리: 익명 401, 허용 목록 밖 403, CSRF 헤더·출처 검사, 잠금과 해제, 유휴 만료, 비밀번호 변경 시 세션 종료, 상태 파일에 평문 비밀번호 없음(0600), 실제 TLS 접속과 인증서 지문 일치.
- 특권 헬퍼: 허용 경로 밖 쓰기 거부, `..` 경로 거부, 1 MiB 한도(256 KiB), root·uid 1000 미만 계정의 키 거부.
- 방화벽: 이름·출발지 주입 거부, `nft -c` 실패 시 저장 파일 보존.
- VPN: X25519 키 파생이 RFC 7748 시험 벡터와 일치, 응답과 상태 파일에 기기 개인 키 없음.
- 유선 설정: 확인하지 않으면 이전 파일로 복구, 데몬 재시작 뒤 복구, `networkctl` 실패 시 되돌림.

## 2. 시험 중에 알게 된 것

- Adw 그룹 설명은 마크업으로 해석된다. `<your API key>` 같은 꺾쇠가 있으면 `Gtk-WARNING` 이 나오고 번역 목록 시험은 이스케이프된 따옴표를 읽지 못한다. 문구에서 꺾쇠와 큰따옴표를 뺐다.
- `http.ServeMux` 는 `/v1/` 패턴과 `GET /` 를 함께 등록하면 충돌한다.
- 데몬 샌드박스(`ProtectSystem=full`, `ProtectHome=yes`) 때문에 `/etc` 와 홈에 쓰는 일은 권한 있는 헬퍼(`systemd-run --pipe`)로 한다. 데몬 자신의 샌드박스는 넓히지 않았다.
- 게이트웨이를 켜면 키를 만들고 지워도 서버 재시작이 필요 없다(이전에는 필요했다). API 응답의 `restart_required` 가 이에 맞게 바뀐다.

## 4. 미검증(실기 또는 외부 확인이 필요한 것)

- **GPU 서버 시작**: 사용자가 보고한 시작 실패의 원인은 로그를 받기 전이라 미확정이다. 실 GPU 오프로드, 처리량, 코딩 에이전트 부하는 확인하지 않았다.
- **덮개 닫기, 절전**: 상시 가동 설정이 실제 노트북에서 막는지.
- **한글 입력**: 실제 키보드의 한/영 키, 오른쪽 Alt.
- **네트워크**: 실 어댑터에서 고정 IP 적용과 확인·복구, Wake-on-LAN, 실제 Wi-Fi, mDNS 이름 해석(Windows·macOS 클라이언트).
- **원격 접속**: 실제 RDP 클라이언트로 xrdp 접속, 실제 WireGuard 피어(휴대폰·노트북) 연결과 `wg0` 인터페이스 생성(E2E 는 기록만 한다), 다른 컴퓨터 브라우저에서 웹 관리 접속과 인증서 경고 흐름.
- **NVIDIA 하이브리드 Xorg, VMware, Secure Boot 등록(MOK)** 은 0.5.1 이전부터 미검증이다.
- **경량화 L6**: 램 기준선은 CI(QEMU)에서 쟀다([memory.md](memory.md) 3.3절). 새 램 목표는 사용자가 정한다(제안은 같은 절).
- **TLS 없는 게이트웨이**: LAN 에서 키가 평문 HTTP 로 오간다. LAN 밖은 VPN 을 쓴다.
