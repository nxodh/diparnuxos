## 2. 시험 중에 알게 된 것

- **추적된 바이트코드**: `tests/qemu/__pycache__/*.pyc` 가 이전 커밋에서 실수로 추적되고 있었고 이전 이름이 들어 있었다. 추적에서 빼고 `.gitignore` 에 넣었다. 흔적 검사는 이런 바이너리까지 본다.
- **원본 로고의 가장자리**: 원본에 반투명 얼룩이 있어 단순 crop 으로는 투명 배경 가장자리가 지저분하다. 원 마스크로 다시 잘라 해결했다.
- **macOS 의 bash 3.2**: `mapfile` 이 없어 흔적 검사를 `git grep` 으로 구현했다. 빈 배열 확장(`set -u`)도 `${arr[@]+...}` 형태로 써야 한다.
- **Firefox 실험**: 이전 실행에서 "Profile Missing" 이 나온 것은 시험이 `HOME` 을 지정하지 않은 탓이다. 시험에서 `HOME` 을 지정하도록 고쳤다.

## 3. CI 결과

- **통과한 실행(38320884366)**: 작업 두 개(lint, ISO 빌드와 부팅 시험)가 모두 성공했다. 데스크톱 세션 E2E 는 약 596초가 걸렸다.
  - **이전 이름 검사**: 린트의 `make check-legacy-name`, 이미지 검사(파일 목록, 패키지 데이터베이스, 설정 파일), QEMU 라이브 세션의 `legacy-name-absent`(파일 이름, 유닛, 그룹, `os-release`, 호스트 이름, 이슈)가 모두 통과했다.
  - **화면 캡처**: 로그인 화면의 아바타와 시작 메뉴 단추가 새 로고(원 안의 D)로 표시되고, 설치기 창의 사이드바 로고와 제목이 새 이름(`Diparnux 0.5.1`)으로 표시된다.
  - **소크 시험(8분, 표본 1에서 7, kB)**: `diparnuxd` 37156 → 37400, Control Center 332120 → 336344, Xorg 144956 → 145604, xfwm4 30260(변화 없음), xfce4-panel 31812(변화 없음), xfdesktop 43964(변화 없음), MemAvailable 3158428 → 3167316. 모든 상한 안이다(램 목표가 아니라 누수 검사의 기록).
  - **ISO 크기**: 1,662,210,324 바이트(약 1.55 GiB). 0.5.0 과 같다.
- **불안정 항목**: 첫 실행(38287232627)은 설치기 창 단계(`installer-still-running`)에서 실패했다. Calamares 가 시작은 되었지만 20초 안에 사라졌다. 같은 코드의 컨테이너 재현(Xvfb)에서는 25초 뒤에도 살아 있었고, 설치기 패키지는 0.5.0 과 이름·이미지·변경 이력만 다르다. 진단(설치기 출력, 저널, dmesg)을 시험에 넣어 다시 돌렸더니 통과했다. 원인은 확정하지 못했고 일시적인 불안정으로 본다. 같은 단계가 다시 실패하면 이번에 넣은 진단이 원인을 남긴다.
